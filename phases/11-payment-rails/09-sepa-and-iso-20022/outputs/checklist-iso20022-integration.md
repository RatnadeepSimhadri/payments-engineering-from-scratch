# Checklist: ISO 20022 Integration

Use this as the acceptance criteria for a bank connectivity project, or as the review list for code that produces or consumes pain, pacs, or camt messages.

## Versions and namespaces

- [ ] The exact message versions are agreed with each counterparty (for SEPA since November 2023: pain.001.001.09, pacs.008.001.08) and recorded per bank.
- [ ] Parsers check the root namespace before reading any field, and reject unknown versions with a message that names both the expected and the received namespace.
- [ ] Writers emit elements in schema order (`xs:sequence`), and output is validated against the official XSD in CI.
- [ ] The counterparty's own implementation guide (optional fields required, multiple `PmtInf` allowed, character set) is linked from the code.

## Identifiers

- [ ] `MsgId` is unique per sender, generated once, and persisted before the file is sent (so a resend reuses it and the bank's duplicate check works).
- [ ] `EndToEndId` is generated by your system per payment, at most 35 characters, unique, stored with the payment, and used as the key for every status, return, and statement match.
- [ ] `TxId` and `UETR` from the bank's side are stored when received.
- [ ] Identifiers avoid leading or trailing `/` and `//`.

## Amounts and totals

- [ ] Amounts are integer minor units in memory and are formatted with `.` and exactly the currency's decimals.
- [ ] `NbOfTxs` and `CtrlSum` (and `TtlIntrBkSttlmAmt` in pacs) are derived from the transactions at write time, never stored separately.
- [ ] Parsers recompute every declared total at every level where it appears and reject a mismatch.
- [ ] More decimals than the currency allows is a parse error, not a rounding.

## SEPA business rules

- [ ] Currency EUR; amount 0.01 to 999,999,999.99.
- [ ] Names at most 70 characters; unstructured remittance at most 140 characters, one occurrence.
- [ ] Text is basic Latin (EPC217-08) or transliterated, unless the bank agrees in writing to a wider set.
- [ ] IBAN check digits and country length validated at data entry (Lesson 11), not only at file creation.
- [ ] BIC optional for the creditor (IBAN-only); if your system is the debtor bank, the BIC directory is current and missing entries fail loudly.
- [ ] `ChrgBr` is `SLEV`; requested execution date is a TARGET business day not in the past.

## Secure parsing

- [ ] DOCTYPE is disallowed in every XML parser that reads counterparty data; secure processing is on; XInclude and external entities are off.
- [ ] A test feeds an XXE payload and a billion-laughs payload and expects rejection.
- [ ] Large files are parsed with a streaming API (StAX) or a size limit is enforced before DOM parsing.

## Lifecycle messages

- [ ] pain.002 / pacs.002 status reports are parsed and joined to payments by `EndToEndId`; rejected payments raise an alert with the ISO reason code.
- [ ] pacs.004 returns and camt.054 notifications update the payment state machine (Phase 12, Lesson 02).
- [ ] camt.056 recall requests (outgoing and incoming) and camt.029 answers have an owner and a runbook.
- [ ] camt.053 statements are reconciled against sent payments daily (Lesson 14).
